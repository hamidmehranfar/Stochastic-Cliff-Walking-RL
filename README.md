# Reinforcement Learning: Monte Carlo and Temporal-Difference Methods

This repository contains three Jupyter notebooks , Cliff Walking environment and  a small helper module implementing and comparing classical **tabular reinforcement-learning algorithms**. The experiments use a custom `StochasticCliffWalkingEnv` environment and focus on policy evaluation, off-policy estimation, and temporal-difference control.

The project focuses on three main problems:

1. Policy learning and evaluation using **Monte Carlo** methods;
2. State-value function estimation using **Dynamic Programming**, **Monte Carlo**, and **Temporal-Difference** methods;
3. Control policy learning using **SARSA**, **Q-Learning**, **Expected SARSA**, and **Double Q-Learning** algorithms.

### Learning objectives

The experiments are intended to illustrate the following concepts:

- Learning value functions from complete episodes versus bootstrapping from current estimates.
- The difference between first-visit and every-visit Monte Carlo updates.
- The distinction between on-policy and off-policy learning.
- The use of importance-sampling ratios to evaluate a target policy using trajectories generated by a behavior policy.
- The effect of the n-step horizon on temporal-difference targets.
- The difference between SARSA, Q-Learning, and Expected SARSA targets.
- The motivation for Double Q-Learning and its use of two independent action-value estimators.

## Introduction to the Problem and Environment

The "Cliff Walking" problem is a classic scenario used to examine an agent's behavior within a grid-based environment. The agent begins in a starting state and must reach a goal state by selecting appropriate actions, all while navigating past dangerous areas (the "cliff"). In this project, the environment is named `StochasticCliffWalkingEnv`, implying that state transitions may be stochastic (probabilistic). The specific transition probabilities and the rewards associated with each transition are defined within the environment file; since this file is not included in the current repository, no assumptions are made here regarding their exact values.

## Notebook 1: Monte Carlo Control and Importance Sampling

### 1. Epsilon-Soft Policy

The function `epsilon_soft_policy(Q, nA, epsilon)` constructs a stochastic policy from the current action-value table.

For a state \(s\), every action receives an exploration probability of \($\epsilon / |A|$). The greedy action receives the remaining probability mass:

$$
\pi(a\mid s)=
\begin{cases}
1-\epsilon+\epsilon/|A|, & a=\arg\max_{a'}Q(s,a'),\\
\epsilon/|A|, & \text{otherwise}.
\end{cases}
$$

This policy combines exploitation with continued exploration. It is epsilon-soft rather than strictly greedy because every action retains a nonzero probability when `epsilon > 0`.

### 2. First-Visit Monte Carlo Control

The function `first_visit_monte_carlo_epsilon_soft` learns an action-value table `Q` using complete episodes.

For every episode, the implementation:

1. Builds an epsilon-soft policy from the current `Q` table.
2. Generates an episode using `generate_episode`.
3. Computes the discounted return at each time step by traversing the episode backward.
4. Uses a set of visited `(state, action)` pairs to retain only the first occurrence of each pair in that episode.
5. Updates the cumulative return sum and occurrence count for that pair.
6. Replaces the corresponding action-value estimate with the sample average.

The return from time step \(t\) is:

$$
G_t = R_{t+1}+\gamma R_{t+2}+\gamma^2R_{t+3}+\cdots.
$$

The incremental sample-average update is:

$$
Q(s,a)\leftarrow Q(s,a)+\frac{G-Q(s,a)}{N(s,a)},
$$

where `N(s, a)` is the number of first-visit updates for that state-action pair.

The notebook trains two policies using `epsilon = 0.1` and `epsilon = 0.01`, then evaluates their greedy action choices in separate rollouts.

**Interpretation:** a larger epsilon assigns more probability to exploratory actions; a smaller epsilon places more probability on the current greedy action. The notebook provides a way to inspect how this choice affects learning curves and the greedy path.

### 3. Greedy Policy Rollout

The helper `mc_run_path` starts an episode and repeatedly selects:

```python
action = np.argmax(Q[state])
```

It records the sequence of states, accumulates rewards internally, optionally renders the environment, and stops when the environment reports termination or when the configured length limit is exceeded.

This is a **greedy evaluation rollout**, not another training procedure: the Q-table is not updated during this function.

### 4. Ordinary and Weighted Importance Sampling

The notebook then investigates off-policy estimation. Episodes are generated using a uniformly random behavior policy:

$$
b(a\mid s)=\frac{1}{|A|}.
$$

A target policy is constructed from a previously learned Q-table. The notebook tests both a deterministic greedy target policy and an epsilon-soft target policy.

For a trajectory segment, the importance-sampling ratio is built from target and behavior probabilities:

$$
\rho = \prod_t \frac{\pi(A_t\mid S_t)}{b(A_t\mid S_t)}.
$$

The implementation processes each episode backward and updates state-action estimates using the accumulated ratio.

#### Ordinary importance sampling (OIS)

`incremental_ordinary_importance_sampling` maintains a visit counter `N` for each state-action pair and uses an incremental update of the form:

$$
Q(s,a)\leftarrow Q(s,a)+\frac{\rho G-Q(s,a)}{N(s,a)}.
$$

#### Weighted importance sampling (WIS)

`incremental_weighted_importance_sampling` maintains cumulative weights `C` and updates:

$$
C(s,a)\leftarrow C(s,a)+\rho,
$$

$$
Q(s,a)\leftarrow Q(s,a)+\frac{\rho}{C(s,a)}(G-Q(s,a)).
$$

The notebook records `max(Q[s])` for selected states (`36`, `29`, and `5`) and plots the resulting histories for OIS and WIS.

**How to read the plots:** compare the variability and stability of the two estimators over the episode count. Importance-sampling ratios can become highly variable, especially when the target policy assigns low probability to actions sampled by the behavior policy. Weighted importance sampling normalizes by cumulative weights and is often more stable in practice.

**Implementation qualification:** the code multiplies the importance ratio by the current action's probability ratio before updating that same `(state, action)` entry. In the standard action-value off-policy Monte Carlo update, the weight for ($Q(S_t,A_t)$) is normally the product of ratios for subsequent actions, beginning at ($t+1$); the current action is already conditioned on by the action-value being estimated.

A second qualification applies to the plotted state-value proxy: the code records `np.max(Q[s])`. This is consistent with a greedy value readout, but it is not generally the state value of an epsilon-soft target policy. For an epsilon-soft policy, the corresponding policy value is:

$$
V_\pi(s)=\sum_a \pi(a\mid s)Q(s,a).
$$

Therefore, interpret the epsilon-soft-target plots as the maximum action-value history used by the notebook, not necessarily as exact estimates of ($V_\pi(s)$).

## Notebook 2: Monte Carlo and TD Prediction

Notebook 2 estimates the state-value function of a uniformly random policy and compares different prediction methods.

The policy is:

$$
\pi(a\mid s)=\frac{1}{|A|}.
$$

### 1. Iterative Policy Evaluation (Model-Based Reference)

`iterative_policy_evaluation` uses the transition model `env.P` to calculate a reference value function.

For each state, it sums over all actions and possible transitions:

$$
V(s)\leftarrow\sum_a\pi(a\mid s)\sum_{s',r}p(s',r\mid s,a)
\left[r+\gamma V(s')\right].
$$

The function repeats full sweeps until the largest change in a state value is below `threshold` (`1e-6`). Updates are performed in place, so values computed earlier in a sweep can be used later in the same sweep.

The resulting array is stored in `V_true` and is used as the reference for calculating RMSE in the prediction experiments.

### 2. Every-Visit Monte Carlo Prediction

`every_visit_monte_carlo_prediction` estimates `V(s)` using returns from complete episodes.

For every episode:

1. An episode is generated under the uniformly random policy.
2. The discounted return is computed backward.
3. Every occurrence of a state is updated, including repeated visits to the same state within one episode.
4. The estimate is maintained using an incremental sample average.
5. The values of states `36`, `29`, and `5` are recorded.
6. RMSE against `V_true` is computed over the full state-value array.

The update is:

$$
V(s)\leftarrow V(s)+\frac{G_t-V(s)}{N(s)}.
$$

Because the method waits for a complete episode return, it does not bootstrap from the current value estimate. Its update targets are full sampled returns.

### 3. TD(0) Prediction

`td0_prediction` uses one-step temporal-difference learning with a fixed step size of `alpha = 0.01`.

For a nonterminal transition, the TD target is:

$$
R_{t+1}+\gamma V(S_{t+1}).
$$

The update is:

$$
V(S_t)\leftarrow V(S_t)+\alpha
\left[R_{t+1}+\gamma V(S_{t+1})-V(S_t)\right].
$$

When the transition terminates or is truncated, the implementation uses the immediate reward as the target and does not bootstrap from the next state.

The notebook compares the estimates for selected states and plots RMSE on a logarithmic vertical scale. This makes differences across a wide range of error magnitudes easier to inspect.

### 4. n-Step TD Prediction

`n_step_td_prediction` generalizes the one-step TD target by combining several observed rewards with a bootstrap value at the end of the n-step horizon.

The intended n-step target is:

$$
G_{t:t+n}=\sum_{i=1}^{\min(n,T-t)}\gamma^{i-1}R_{t+i}
+\mathbb{1}_{t+n<T}\gamma^nV(S_{t+n}),
$$

where `T` is the time step at which the episode ends. When the episode ends before the n-step horizon, the return contains the available rewards and no bootstrap beyond the terminal transition.

The notebook evaluates:

```python
all_n = [1, 2, 4, 8, 100]
```

and compares the resulting RMSE curves. A larger `n` uses more sampled rewards before bootstrapping; a smaller `n` relies more heavily on the current value estimate.

### 5. n-Step TD with an Adaptive Step Size

`n_step_td_prediction_with_adaptive_alpha` uses a per-state visit/update counter `N` and sets:

$$
\alpha(s)=\frac{1}{N(s)}.
$$

The step size is therefore reduced as a state receives more updates. The notebook runs this variant with `n = 100` and compares its RMSE history with the every-visit Monte Carlo history.

This adaptive-step-size experiment calls the same n-step return calculation as the fixed-step-size implementation, so it inherits the reward-indexing issue described above. Its curve should not be used to support a conclusion about the correctness or relative performance of standard n-step TD until the return calculation is fixed.

The function also accesses `V_true` as a global variable when calculating RMSE rather than receiving the reference values as an explicit argument.

## Notebook 3: Temporal-Difference Control

Notebook 3 compares algorithms that learn action values and derive a policy from the learned Q-table.

All four algorithms use the epsilon-soft policy implemented in this notebook. The default parameters are:

```python
episodes = 5000
gamma = 0.99
alpha = 0.1
epsilon = 0.1
```

### 1. SARSA

SARSA is an **on-policy** temporal-difference control algorithm. Its update uses the next action actually selected by the current behavior policy:

$$
Q(S_t,A_t)\leftarrow Q(S_t,A_t)+\alpha
\left[R_{t+1}+\gamma Q(S_{t+1},A_{t+1})-Q(S_t,A_t)\right].
$$

For a terminal transition, the implementation uses the reward-only target and does not bootstrap.

The notebook records episode returns and uses repeated runs to calculate mean return curves and standard deviations.

### 2. Q-Learning

Q-Learning is an **off-policy** temporal-difference control algorithm. It uses the maximum estimated action value at the next state, regardless of which action the behavior policy would select:

$$
Q(S_t,A_t)\leftarrow Q(S_t,A_t)+\alpha
\left[R_{t+1}+\gamma\max_a Q(S_{t+1},a)-Q(S_t,A_t)\right].
$$

The notebook samples actions using an epsilon-soft policy but uses the greedy maximum in the update target. For terminal transitions, it uses the immediate reward only.

The implementation also records the maximum action value at the start state (`state = 36`) after each episode. This history is later compared with the corresponding Double Q-Learning estimate.

### 3. Expected SARSA

Expected SARSA uses the expected next-state action value under the current policy rather than the value of one sampled next action or the maximum action value:

$$
Q(S_t,A_t)\leftarrow Q(S_t,A_t)+\alpha
\left[R_{t+1}+\gamma\sum_a\pi(a\mid S_{t+1})Q(S_{t+1},a)-Q(S_t,A_t)\right].
$$

The implementation obtains the epsilon-soft action probabilities for `next_state`, computes the probability-weighted sum of its Q-values, and uses that expectation as the bootstrap term. As with the other control implementations, the terminal transition uses a reward-only target.

The notebook compares Expected SARSA, SARSA, and Q-Learning over 10 runs of 5,000 episodes each. Note that the SARSA curve is affected by the next-action state bug described above.

### 4. Double Q-Learning

Double Q-Learning maintains two separate action-value tables, `Q1` and `Q2`, to reduce the overestimation associated with using the same estimates both to select and evaluate the maximizing action.

The behavior policy is derived from their sum:

$$
Q_{\mathrm{sum}}(s,a)=Q_1(s,a)+Q_2(s,a).
$$

At each step, one table is selected at random for updating. If `Q1` is selected, the action is chosen using `Q1` and evaluated using `Q2`:

$$
Q_1(S_t,A_t)\leftarrow Q_1(S_t,A_t)+\alpha
\left[R_{t+1}+\gamma Q_2(S_{t+1},\arg\max_a Q_1(S_{t+1},a))-Q_1(S_t,A_t)\right].
$$

If `Q2` is selected, the roles are reversed:

$$
Q_2(S_t,A_t)\leftarrow Q_2(S_t,A_t)+\alpha
\left[R_{t+1}+\gamma Q_1(S_{t+1},\arg\max_a Q_2(S_{t+1},a))-Q_2(S_t,A_t)\right].
$$

The implementation uses `Q1 + Q2` to select behavior actions and to determine the best action at the start state. The start-state estimate recorded in the notebook is the average of the two selected table values:

$$
\widehat{Q}(s,a)=\frac{Q_1(s,a)+Q_2(s,a)}{2}.
$$

The notebook averages results across 10 independent runs and compares Double Q-Learning with standard Q-Learning.

## Results and Interpretation

The notebooks generate learning curves and value-estimation plots rather than a consolidated numerical benchmark table. The following are the comparisons the code is designed to support, together with the interpretation limits that should be kept in mind.

### Monte Carlo control and exploration

The first notebook compares learned action-value tables for `epsilon = 0.1` and `epsilon = 0.01`, then follows their greedy policies. It also plots average episode-start return across repeated runs for `epsilon = 0.1`.

A larger epsilon increases the probability of selecting non-greedy actions; this can improve exploration but can also reduce the return of an individual exploratory episode. A smaller epsilon behaves more greedily. 

### Ordinary versus weighted importance sampling

The first notebook plots the estimates for three selected states. The plots are intended to show how the estimates evolve as more behavior-policy episodes are collected.

Ordinary importance sampling can have high variance because it relies directly on products of probability ratios. Weighted importance sampling normalizes by cumulative weights and often produces more stable estimates.

### Monte Carlo versus TD prediction

The second notebook compares value estimates with the model-based reference and plots RMSE over episodes.

The conceptual comparison is:

- **Every-visit Monte Carlo** uses complete returns and updates every occurrence of a state. It does not bootstrap, so the target can have high variance.
- **TD(0)** bootstraps from the next state's current estimate. It can update before the episode is complete, but its behavior depends on the step size.
- **n-step TD** interpolates between short-horizon bootstrapping and longer sampled returns.

The plotted RMSE is computed across all states, not only the three states whose trajectories are separately displayed. The n-step implementation currently omits a reward at the end of its accumulation range, so its curves are not a valid basis for ranking standard n-step methods until the bug is fixed.

### On-policy and off-policy control

The third notebook compares episode returns for SARSA, Q-Learning, and Expected SARSA, followed by a Q-Learning versus Double Q-Learning comparison.

At the algorithmic level:

- SARSA evaluates the action actually sampled from the policy.
- Q-Learning uses the greedy next-state action value in its target.
- Expected SARSA averages next-state action values under the policy.
- Double Q-Learning separates action selection and action evaluation across two estimators to mitigate maximization bias.

The SARSA implementation has a next-action sampling bug, and the return-curve plotting helper has an incorrect uncertainty-band calculation (see below). Therefore, the SARSA comparison and shaded standard-deviation regions should be corrected before using the plots as evidence for a performance ranking.
